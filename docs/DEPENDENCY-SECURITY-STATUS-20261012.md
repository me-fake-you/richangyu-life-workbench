# 构建依赖安全处理范围

日期：2026-10-12。此记录区分私有部署工程与公开原生开发工程。

## 可修复的压缩包组件

私有部署工程保留旧 Capacitor CLI 6，压缩包依赖原为 tar 6.2.1。
本次只将该 CLI 的 tar 依赖锁定到官方 7.5.21，不升级整个 CLI，
不改旧安卓工程、手机签名或个人数据。
旧 CLI 使用默认导入，而 tar 7 的导出形式不同。本次加入受约束的安装后适配：
只改本地 CLI 6 模板工具中的一处导入，核对 tar 精确版本、目标路径和预期源码；
未知版本或代码形状必须失败。不会改变 tar 的解压实现、关闭检查或回退有漏洞的依赖。

[官方公告 GHSA-r292-9mhp-454m](https://github.com/advisories/GHSA-r292-9mhp-454m)
列出修复版 7.5.21；包元数据和下载来源由 npm 官方仓库核实。
此跨主版本间接依赖替换需通过实际模板解压兼容测试，不只检查版本号。
公开原生工程没有旧 Capacitor CLI，不需要为了数字好看引入它或改其锁文件。

## 未被安全“清零”的上游问题

[braces 官方安全公告](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)
当前影响 <=3.0.3，尚无公告确认的修复版本。
相关链路包括 Next ESLint 插件与 Vinext 构建插件。

不通过降级框架、关闭 ESLint、过滤 npm audit 输出或修改公告匹配来宣称已解决。
这些是待处理的构建依赖风险；仅生产依赖审计零告警不代表整体零风险。
应继续关注真实上游补丁或经过完整兼容验证的构建方案，避免处理不可信构建输入。

本说明不预先宣布本轮测试结果或最终告警数量。
发布证据应分别记录完整审计、生产依赖审计、模板解压测试、
完整类型/规范/测试/编码/构建及实际私有部署状态。
