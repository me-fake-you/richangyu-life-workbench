# 日常屿 Android 1.8.10-preview 中文上手指南

> 先安装，再绑定和登录，最后打开热量与饮食。本指南不代表手机实测已完成，也不代表已经上架应用商店。

## 1. 下载和安装

[打开 1.8.10 发布页](https://github.com/me-fake-you/richangyu-life-workbench/releases/tag/v1.8.10-preview)，在 Assets 中选择 `life-workbench-v1.8.10-preview.apk`。

[直接下载 APK](https://github.com/me-fake-you/richangyu-life-workbench/releases/download/v1.8.10-preview/life-workbench-v1.8.10-preview.apk)

- 下载的是 `.apk` 安装包，不是 Source code 压缩包。
- 微信内无法下载或安装时，可用手机系统浏览器打开同一个 GitHub 发布页。只从本项目官方发布地址取得文件。
- 如果完整下载后的文件名变成 `.apk.1`，可在文件管理器中将末尾改回 `.apk`。改名不能修复下载中断或文件损坏。
- 手机可能要求允许当前浏览器或文件管理器安装应用。只对这次可信来源操作授权，不要关闭全局安全保护。
- 已发布的 1.8.9-preview 和本版使用同一固定预览签名，可尝试覆盖安装。更早版本不能一概保证覆盖安装；如果提示签名冲突，先保留原 App 和数据，反馈提示，不要急着卸载。
- 本版最低 Android 版本为 5.1。实体手机兼容性仍需实际确认。

本版包名：`com.richangyu.lifeworkbench.preview`；版本号：`1.8.10-preview`；版本代码：`10012`。

## 2. 绑定自己的工作台

首次启动未绑定时，App 只展示连接引导，不会读取云端记录。这不等于功能已经删除。

1. 点击“绑定我的工作台”，或连接失败页的“设置 / 更换工作台地址”。
2. 输入自己可信、兼容本客户端的 HTTPS 工作台根地址，例如 `https://your-workbench.example.com`。示例地址不能用于实际连接。
3. 不填邮箱、密码、API 密钥、登录页面路径或带参数的授权链接。
4. 核对 App 提示的域名，再连接，并使用有权访问该工作台的账号完成授权。
5. 看到原生首页和云端记录后，再操作日程、打卡和饮食。填写地址成功不等于登录授权成功。

授权过程中出现网页是登录流程的一部分，不代表全部业务都必须在网页使用。如果授权后一直停留网页、反复登录或仍显示未连接，请保留提示截图反馈，不要反复重新安装。

公开 APK 不内置开发者的私人工作台地址或 AI 密钥，也不会自动赋予任何人访问私人数据的权限。随便填写一个 HTTPS 网站并不能把它变成兼容的工作台。

## 3. 热量功能在哪里

连接成功后，从以下任一位置进入：

- “首页”中的“热量与饮食”卡片，点击“打开热量与饮食”。
- 底部“我的”中的“热量与饮食”卡片，点击同一按钮。

可查看每日热量、营养素、饮水，并记录餐食。照片支持拍摄或从手机选择；照片上传属于记录餐食操作，不是不会保存的纯预览。

如果看不到入口，先确认 App 是 1.8.10-preview，再确认已完成绑定与登录。网页版和 App 内置界面不保证所有功能完全一致，本版仍是预览客户端。

## 4. 先检查图片 AI，不新增记录

进入“热量与饮食”，使用“检查图片 AI 连接”，阅读提示并确认。

- 只发送程序生成的测试色块，不上传你的餐食照片。
- 会使用提供商额度，但不会新建餐食、饮水或修改设置。
- “已配置”只说明服务端设置存在，不证明模型可用。
- 只有本次检查返回验证成功，才证明当时的图片接口识别了测试图。它不证明热量估算准确，也不证明手机拍照、餐食保存或同步已经通过实测。
- 检查失败时不会自动启用付费后备服务。实际可用额度以提供商账号为准，不能保证无限免费。

先把检查结果截图反馈，再决定是否试记一餐。截图前遮住账号和私人信息，不要提供 API 密钥、密码或授权链接。

## 5. 试记一餐和核对同步

以下步骤会真实新增数据，请只在自己的工作台中进行，并使用自己愿意上传的餐食照片。

1. 只提交一次餐食，等待结果。
2. 检查食品、份量、热量及营养素。AI 结果是估算，不是测量结果。
3. 查看回执中的估算来源。图片识别、图片加个人食物记忆、文字估算和手动填写不是同一回事；照片保存成功不等于图片 AI 已识别成功。
4. 如果发现不准确，使用界面已有的编辑能力修正；找不到修改入口时，反馈问题，不要为了修正重复新建同一餐。
5. 在网页版查看同一天的记录和总量，再回 App 刷新核对。

若显示“保存结果待核对”或发生保存超时，先同步并查看是否已经生成记录，不要直接重复提交。同步依赖相同工作台、有效授权和网络，不是承诺任意离线操作都会自动合并。

## 6. 常见提示与处理

| 提示或现象 | 先做什么 | 不要据此推断 |
| --- | --- | --- |
| 待绑定 / 尚未设置地址 | 设置可信工作台根地址 | 功能被删除 |
| 授权后仍未连接 / 401 / 403 | 保留原提示，确认账号确实有该工作台访问权 | 一定是 AI 模型出错 |
| 图片 AI 未配置 | 联系自己工作台的维护者配置图片模型 | 文本 AI 必然也不可用 |
| 配置存在但检查失败 | 反馈检查原文及模型显示信息 | 已配置就等于可识别 |
| 额度 / 限流提示 | 按提示等待，不连续点击检查 | 自动切换其他付费服务 |
| 模型不可用 | 反馈给维护者处理模型支持 | 换手机就一定解决 |
| 检查超时 | 稍后再检查；检查本身不保存餐食 | 检查已经通过 |
| 餐食保存超时 | 先核对云端记录，避免重复提交 | 服务器一定没有保存 |
| APK 安装签名冲突 | 保留旧 App 和数据，反馈版本及提示 | 必须立刻卸载旧版 |

## 7. 工作台升级后，App 会跟着升级吗

- 使用同一个工作台时，服务端能力和云端数据更新可供 App 后续联网访问，但受授权、缓存和接口兼容性影响。
- App 内置原生页面、手机权限、按钮和导航的改变，需要安装新的 APK；网页更新不会自动改写旧 APK。
- 网页新增功能不代表立即出现对应原生入口。不要把服务器更新和安装包更新混为一谈。

## 8. 别人能用吗

别人可以取得公开预览安装包，但不能因此登录开发者的私人工作台。当前私人站点没有开放公共注册。

其他用户需要自己拥有、并获授权访问的兼容工作台。独立多人服务尚未部署，本版没有完成应用商店上架。公开宣传请称“安卓预览版、源码公开”，不要宣称“所有人直接注册”“无限免费 AI”或“全部手机功能已实测”。
