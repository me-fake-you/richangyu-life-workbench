# 数据与隐私

日常屿可能保存高度敏感的日记、照片、位置、财务和客户信息。部署者需要理解数据存在哪里、什么时候会离开自己的基础设施。

## 登录与他人使用

当前数据按整个工作台保存，记录和日程没有逐账号归属字段。手机接口会核对登录身份，但登录只确认访问者是谁，不会自动为每个人创建独立数据空间。设备 ID、私密标记或展示用邮箱都不能替代服务器端用户隔离。

个人部署应保持现有受限访问范围。邀请其他账号进入同一部署可能让对方接触工作台中的数据，不能把平台的访问授权当作应用内只读或数据隔离。推荐他人绑定各自独立部署、数据库和附件存储，不共享个人账号、授权链接或 AI 密钥。

自托管时还必须保护所有 API 和附件访问；只给页面加登录不够。面向公众的多用户版本需要单独完成账号归属、每次查询和写入的权限、AI 上下文隔离、备份导出删除边界及防串号测试，本轮没有宣称已实现。详见 [安卓手机验收与他人试用](ANDROID-PHONE-ACCEPTANCE.md)。

## 数据位置

| 数据 | 默认位置 | 说明 |
| --- | --- | --- |
| 记录、日程、表格、财务、总结 | Cloudflare D1 | 结构化数据与关联 |
| 照片、语音、附件、票据、归档 | Cloudflare R2 | 数据库保存对象键和元数据 |
| 离线待同步内容 | 当前设备浏览器 | 联网后同步，清理浏览器数据可能丢失 |
| API 密钥 | 本地 `.env.local` / Worker Secret | 不进入仓库和客户端包 |
| AI 请求内容 | 所选模型提供方 | 只在用户触发分析或后台任务时发送 |

## AI 会收到什么

根据功能，模型可能收到：

- 用户选择的记录文本、标签和日期；
- 用于总结的非私密记录片段及来源 ID；
- 用户主动上传用于识别的餐食或资料图片；
- 情报源的标题、摘要和链接；
- 为回答问题而检索出的相关上下文。

私密记录默认不进入普通 AI 总结。部署者仍应核查自己选择的模型供应商条款、日志保留和数据地域。不要把身份证件、完整支付凭证、密码或无关个人信息交给模型。

## 私密空间边界

私密空间执行产品级隔离：

- 不出现在普通首页、搜索、默认总结和往年今日；
- 通知不显示正文；
- 导出需要单独确认；
- 切换后台时可模糊；
- 媒体读取需要对应权限和上下文。

这不是零知识或端到端加密。Cloudflare 账户管理员和拥有底层数据库/对象存储权限的人仍可能读取数据。

## 财务和客户数据

- 账户转账不计作收入或支出；
- 应赚、应收、到账和账户交易分开保存；
- 首页可以隐藏余额，但这不替代后端访问控制；
- 客户联系方式、票据和收款截图导出前必须再次确认；
- 分享截图或日志前应移除金额、姓名、电话、地址和对象 URL。

## 备份与删除

- 导出或恢复前进行预览和校验；
- 删除进入回收站，永久删除保留审计记录；
- 定期同时验证 D1 数据和 R2 对象的恢复能力；
- 至少保留一份与 Cloudflare 账户隔离的加密备份；
- 更换设备前确认离线队列已同步。

## 公开仓库安全

禁止提交：

- `.env.local` 或任何真实密钥；
- `.openai/hosting.json`；
- D1/R2 备份和生产数据库；
- 真实照片、票据、客户资料；
- 带个人路径、账号或生产站点 ID 的诊断日志。

仓库中的 `examples/demo` 只包含虚构数据。

## 饮食估算

单张图片无法准确知道食材克重、食用油、调料和隐藏配料。热量与营养素结果必须允许人工修正，仅用于日常记录，不可替代医学诊断或专业营养建议。
