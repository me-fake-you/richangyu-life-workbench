# 多人版账号空间基础阶段

用户已选择另建独立多人服务，保留现有个人工作台不变。本轮新增独立空间基础，先实现一个账号只能创建、读取和修改自己的空间资料；不会把未隔离的旧数据接口一起开放。

## 本轮交付

新增 `multiuser/` 服务目录、默认关闭的 Worker 配置、空间归属存储和双账号隔离测试。现有私人站点、数据库、安卓 App、签名及服务器 AI 配置保持原样，没有迁移旧记录或邀请外部用户。

空间 ID 由服务器生成，当前身份使用可信网关提供的稳定账号 ID，邮箱只属于展示信息，客户端不能指定归属。唯一约束防止同一账号重复创建多个空间；查询和改名按当前账号做参数绑定。没有空间时返回 null，不拿其他账号的空间或旧数据填充。

## 尚未完成

- 新独立站点的注册、托管和真实身份网关验收。
- 逐空间隔离的记录、打卡与日程接口，以及手机授权返回流程。
- AI 草稿归属、签名、上下文和使用额度隔离。
- 附件、备份、导出和删除的归属校验。
- 真正两个账号登录后的端到端防串号验收。
- 多人版 App 的公开下载与应用商店发布。

这些项目没有标为通过。当前 1.8.7 App 仍用于原兼容工作台，不能绑定尚未完成的多人服务。

## 本轮测试范围

测试用内存 SQLite 执行真实空间 SQL，并适配 D1 的 prepare、bind、first 和 run 方法。覆盖双账号读写隔离、邮箱变化、账号大小写、伪造归属字段、查询选择器、重复与并发创建、同源写入、输入限长、错误脱敏及不接触旧记录。

这些测试模拟已由可信网关认证的身份，不证明线上身份头不可伪造，也不替代真实 OAuth 登录、D1 云端并发或手机同步验收。只有身份网关、独立数据库和业务接口逐项验收后，才考虑扩大访问范围。

## 后续实施顺序

1. 将记录、打卡和日程接到独立空间，所有查询与写入同时约束空间和账号。
2. 完成手机授权与原生页面接入，不让 App 退回单用户数据接口。
3. 隔离 AI、附件、备份和导出删除，并设置公众服务的额度与滥用防护。
4. 建立独立站点，用两个真实账号完成读写、同步、登出重登和防串号验收，再决定是否开放。

## 实现依据

SQL 使用 [Cloudflare D1 参数绑定接口](https://developers.cloudflare.com/d1/worker-api/prepared-statements/)，测试数据库使用 [Node 22.13 SQLite 接口](https://nodejs.org/download/release/v22.13.0/docs/api/sqlite.html)。构建仅使用 Wrangler dry-run，不进行线上部署。
