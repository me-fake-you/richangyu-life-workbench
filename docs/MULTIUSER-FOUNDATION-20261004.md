# 多人版账号空间与内容基础

更新：2026-10-08。用户已选择另建独立多人服务，保留个人工作台不变。这里提供服务端基础，不是已经可供公众注册或安卓绑定的完整服务。

## 已实现的源码范围

- 使用可信 Sites 身份网关提供的稳定账号 ID 决定空间归属；邮箱、设备 ID 和客户端字段不能决定归属。
- 每个账号最多一个服务器生成的空间，查询、创建和改名使用当前账号的参数绑定。
- 可选 `/api/content` 接口提供自己的纯文本记录和单次日程；创建由服务器生成 ID，修改和软删除要求已观察到的修订。
- 请求回执约束重复提交；查询同时按空间归属和账号约束，最多返回 100 项，并提示是否截断。
- 独立的 `MULTIUSER_DB` 绑定；没有回退到个人工作台 `DB`、旧记录、附件或 AI 服务的路径。
- 基础开关默认关闭；内容接口还需单独启用，示例不含数据库 ID、个人域名或秘密。
- 本轮能力标识按配置和数据库接口可用性生成：记录、日程只在内容条件满足时显示为可用；打卡、AI、附件和备份仍为 false。

上述内容描述实现，不是已经通过本轮检查或实际部署的结论。能力开关不能证明可信身份网关已安全部署，更不证明手机已验收。

## 手机与公共使用的明确边界

当前服务没有现有 App 所需的完整 `/mobile-connect` 和 `/api/mobile` 协议。健康信息明确返回 `nativeBindingReady=false`、`registrationOpen=false` 和 `fullWorkbenchReady=false`。

不能把拿到一个空间 ID、内容接口可用、配置开关打开或一份成功的构建当作公共 App 已完成。当前安卓预览继续绑定各自兼容的个人工作台；不要把他人引入你的私人站点。

## 启用条件与状态信息

`MULTIUSER_FOUNDATION_ENABLED=true`、`MULTIUSER_AUTH_MODE=sites-dispatch` 和可用独立数据库共同控制空间能力。记录与日程还需要 `MULTIUSER_CONTENT_ENABLED=true` 及数据库批处理能力。

健康信息只披露阶段、配置状态和能力布尔值，不返回账号、空间 ID、数据库 ID、密钥或个人站点。公开健康信息不是认证接口。

只有独立站点的身份网关已验证、身份头不能被访客伪造、数据库与私人部署分离后才可启用。普通公开 Worker 不得直接信任账号请求头。

## 仍需完成的交付

1. 独立站点托管、真实登录与可信身份网关验收。
2. 原生 App 的独立服务登录返回、稳定账号范围和兼容协议，不回退到个人数据。
3. 打卡、营养、兼职与财务、AI 签名草稿和上下文的逐账号接口及原生覆盖。
4. 附件、分页、导出、备份、注销与删除的完整归属校验。
5. 两个受控真实账号的读写、重试、修改冲突、登录切换及防串号实测。
6. 完整检查、实际手机验收、可下载新包和必要发布授权。

这些交付没有被削减为只提供空间或只读记录。总体 App 目标继续包含主要原生功能、同步、安全检查、正式签名与商店准备。

## 检查证据范围

历史测试使用内存 SQLite 执行实际空间和内容 SQL，并适配 D1 方法。它们模拟已由可信网关认证的身份，不证明线上请求头不可伪造，不替代 D1 云端并发或真实 OAuth 和手机验收。

本轮状态标识与文档修改未运行新检查、未部署、未打包、未修改个人数据或签名。后续需经允许执行对应检查后，记录确切修订和结果。
