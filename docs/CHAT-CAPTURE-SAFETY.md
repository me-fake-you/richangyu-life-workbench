# 聊天记事与日期安全

## 本轮升级

- 所有待确认内容都明确显示“预览，尚未保存”，不使用模型生成的“已记录、已安排”等完成提示。
- 相对日期按 Asia/Shanghai 解释，包括今天、明天、后天、昨天、前天及大前天、大后天。
- 单日请求核对生成的实际日期；多天或重复安排不强行约束为同一天。
- 聊天中的日程日期不一致时，仅用明确日期纠正一次。仍然不一致则不提供可保存预览。
- “安排计划”在生成前明确日期，生成后再次核对，错误计划不能进入签名预览。
- 生活记录和财务记录不会为纠错而改写用户原话。日期不一致时先请求补充。

## 保存边界

识别、追问和生成预览不等于保存。只有用户点击确认才调用原有保存接口。
签名、用户绑定、15 分钟有效期、冲突检查、事务保存及重复提交保护继续沿用原有实现。
未到账收入只生成待收款预览，不预先计为收入，也不推断收款账户。

## 免费额度

使用服务器端 Groq 配置，不启用付费后备服务。只有发现日程日期不一致时才最多多发起一次识别请求，这次请求也占用免费额度。
取消请求、额度不足或服务失败时，不应把未完成的识别描述为已经保存。

## 验证状态

本轮实现依据上一轮手机尺寸下的页面检查发现的问题。构建和发布不等于完整业务验证；真实保存、日期纠错及安卓安装包仍需独立测试。
