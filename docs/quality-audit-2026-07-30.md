# 时间表与情报中心质量审计（2026-07-30）

本次审计来自真实网页操作和用户截图，目标是把“能录入”提升为“时间准确、可维护、可批量使用、内容可读”。

## 已确认问题

| 严重度 | 问题 | 根因 | 修复 |
| --- | --- | --- | --- |
| P0 | 选择 09:30—10:30 后显示为 17:30—18:30 | `datetime-local` 的无时区字符串直接交给 UTC 服务器解析，浏览器再按北京时间显示，产生二次 +8 小时 | 浏览器提交前转为 ISO UTC；API 对旧客户端携带的 `timezoneOffset` 做兼容转换；指令栏和情报任务入口同步修复 |
| P0 | 日程内容不能完整编辑 | 铅笔按钮只调用两个 `window.prompt` 修改时间，标题、分类、地点、人物、项目、备注、提醒和重复规则没有编辑入口 | 铅笔按钮改为完整编辑弹窗；重复日程明确提示会同步整个系列 |
| P1 | 日程只能逐条添加 | 新建弹窗只支持单个对象，API 也只有单条创建动作 | 新增“单个安排 / 批量安排”；批量行支持标题、日期、起止时间、分类，以及统一地点、项目、提醒和备注；单次上限 50 项 |
| P1 | 点击空白日期仍需重新选日期 | 空白日按钮没有把所属日期传给新建弹窗 | 点击某一天的“安排”后自动预填该日期 |
| P1 | 热点没有图片 | 情报实体没有图片字段，RSS/网页抓取没有提取媒体信息，前端卡片也没有图片区域 | 新增 `image_url`；支持 RSS media/enclosure、正文图片、Open Graph 和 Twitter 图片；缺图时显示来源占位图 |
| P1 | 日报显示 `**`、`###`、`---` 等原始 Markdown | 简报正文作为普通字符串直接渲染 | 新增安全 Markdown 渲染器，支持标题、粗体、列表、分隔线和公开链接，不使用原始 HTML 注入 |
| P1 | 远程图片直连存在隐私、失效和安全边界问题 | 浏览器直接访问第三方图片会暴露来源请求，任意 URL 代理也可能造成 SSRF | 新增按情报 ID 读取的受控图片代理；限制协议、内网地址、重定向、内容类型、超时和 8MB 大小 |

## 回归覆盖

- 单元/契约测试校验北京时间 09:30 对应 `2026-07-30T01:30:00.000Z`。
- 校验日程创建、批量创建、完整编辑三个 API 契约。
- 校验指令栏不再提交裸 `datetime-local` 字符串。
- 校验情报图片字段、抓取、代理和前端展示链路。
- 校验简报不再通过 `dangerouslySetInnerHTML` 渲染。
- 桌面端与手机端在部署前执行真实浏览器操作回归。

## 数据说明

新创建和重新编辑的日程都会使用正确时区。历史上已经以错误时区保存的日程不会被数据库迁移静默批量改写，避免误伤从其他时区或日历导入的记录；应通过新的完整编辑弹窗核对并保存。此次截图中的“论文撰写”会在上线回归时改回 09:30—10:30。
